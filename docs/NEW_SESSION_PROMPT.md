# 新 Session 启动 Prompt（产品经理视角优化）

> 用法：开一个新的 Claude Code session，工作目录设为本项目根目录
> `~/Desktop/AI工程项目/指数小程序`，然后把下面 ``` 之间的内容整段贴进去。

---

```
你现在的角色是这个产品的产品经理，不是工程师。

请先读 docs/PRODUCT_PLAN.md（自包含，不需要其他上下文），
再读 docs/STATUS.md 了解当前进度。想看实物可以直接在浏览器打开
prototype/index.html（数据已内联，双击即可，无需服务器）。

背景：这是一个微信小程序，「全球 48 个国家主权股指的涨幅排行榜」。
技术底座（P1）已经跑通并对 Yahoo Finance 交叉验证过，数据是可信的。
现在需要的不是技术方案，而是**产品层面的批判和打磨**。

我希望你做这几件事：

1. 先说结论：这个产品现在最大的问题是什么？不要面面俱到，
   给我你认为最要命的 2-3 条，并说明为什么。

2. 回答 PRODUCT_PLAN.md 第九节列出的 9 个开放问题。
   有明确推荐就直接给推荐，不要罗列所有选项让我选。
   如果你认为某个问题问错了方向，直接说。

3. 挑战第三节的三条「核心设计主张」（货币口径切换、交易日对齐、
   拿不到就显示「—」）。这三条是我们刻意坚持的，但如果你认为其中
   某条在产品上得不偿失，请直接反驳——我要的是真实判断不是附和。

4. 设计首屏。现在的首屏是一张排行榜表格（可以打开原型看）。
   请给出你认为更好的首屏方案，说清楚用户打开小程序后的 3 秒内
   应该看到什么、记住什么。

5. 给一版从现在到上线的产品路线图，按「用户价值 ÷ 实现成本」排序，
   明确告诉我哪些该砍。注意 P4 里规划的热力图、分享长图、分年度矩阵
   都还没做，你可以重排优先级甚至砍掉。

几个硬约束，优化方案必须在这些边界内：
- 不做个股、不荐股、不给买卖建议、不挂钩具体 ETF 代码、不做行情推送。
  这是为了规避微信金融类目审核风险，不可协商。
- 数据每日收盘后更新一次，不做盘中实时。
- 估值分位第一版不做（全球各国 PE/PB 历史序列无稳定免费数据源）。
- 我目前只有个人主体，正式发布走不通，先做到体验版完整可用。

输出请直接写成 docs/PRODUCT_REVIEW.md，不要只在对话里说。
写完告诉我你改了什么、为什么。
```

---

## 附：如果想换个角度，可以替换第 1 条

**偏增长**：
```
1. 假设这个产品已经做完并发布，但三个月后日活只有 20。
   请倒推出最可能的三个失败原因，并针对每个原因给出现在就该做的改动。
```

**偏竞品**：
```
1. 先去调研中文市场上「全球股市涨幅对比」这个需求现在被什么产品满足
   （雪球、同花顺、英为财情、Wind、各类公众号图表等），
   说清楚我们和它们的差异点到底成不成立。
```

**偏用户**：
```
1. 给我画 2-3 个具体的用户画像（不要泛泛而谈"投资者"），
   说清楚他们在什么场景下会打开这个小程序、打开后想解决什么问题、
   看完之后会做什么动作。然后判断当前的产品设计是否真的服务了他们。
```
