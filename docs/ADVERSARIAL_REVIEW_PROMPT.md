## 这个产品是什么

「全球股市涨幅排行」微信小程序：27 个国家与地区、33 个指数，
按选定时间区间排涨幅。核心设计主张有三条：

1. **三种计价口径**（人民币默认 / 美元 / 原币种）。跨国比较不换算货币等于没比。
2. **交易日对齐**：各国收盘时点不同，每个指数取自己最近一个已收盘交易日；
   区间端点取「该日或之前最近一个交易日」的收盘价，不插值。
3. **拿不到就显示「—」**，不用首日数据充数、不估算填充。

## A 部分：代码与数据正确性

**以下是我（上一个 session）自己最不确定的地方，请优先攻击。
不要因为我列出来了就认为已经处理好——恰恰相反，这些是我心里没底的。**

1. **外币口径缺失时退回原币值参与排名**（index.js 的 `val()`、detail.js 同理）。
   缺汇率的市场会用原币涨幅进榜，标一个 `*`。
   我的理由是「不让市场因缺一个口径而消失」。但这等于**在同一个榜单里混用了
   两种单位**。从金融角度这是否根本站不住？如果站不住，正确做法是什么？

2. **「今日」窗口跨了不同日历日**。埃及交易所周日到周四交易，它的「最近一个
   交易日」常与其余市场差一到两天。榜单把这些放在一起排名。
   上一轮产品评审建议直接砍掉「今日」，我以「所有窗口都有同样错位」为由否决了。
   我的反驳对吗？

3. **多年期窗口用累计涨幅而非年化**。「近3年 +134.74%」直接显示累计值。
   专业场景通常看年化（CAGR）。这算不算误导？

4. **名次变化 Δ 的语义**（snapshot.js 的 `buildRankDelta`）：把窗口终点整体
   往前挪 7 个自然日再排一次名，与当前名次做差。这对「今年以来」是合理的
   （起点不动、终点后退），但对「近1月」意味着起点也跟着挪了。这个语义对吗？

5. **月末点位推导的自定义区间**（`buildMonthly`）。月末取「该月最后一天或
   之前最近一个交易日」。当月取最新交易日。跨月计算时有没有边界错误？
   数值精度用了 8 位有效数字（起初用定点 3 位小数，导致印尼/越南指数换算成
   美元后相对误差达 0.13%）——8 位够吗？

6. **同一国家多个指数**。中国有 4 个（上证/深成/创业板/沪深300）、美国 3 个、
   香港 2 个。切到「全部」时榜单里同一国家反复出现，而这个产品的主语是国家。
   这对「国家排行」的语义是不是破坏性的？

7. **「该日或之前最近一个交易日」的回溯没有上限**。如果某市场长期停市，
   端点可能回溯到很久以前而用户毫无感知。要不要设阈值？

8. **数据源的静默失败**。`build-data.js` 里个别指数抓取失败不会中断构建
   （只有全挂才 exit 1）。这意味着某个市场可能悄悄从榜单消失而没人发现。

除上述外，也请自己通读代码找别的问题。特别关注：
- `snapshot.js` 的日期运算（`minusMonths` / `shiftDays` / 月末 cutoff / ISO 周）
- 汇率换算的方向（fx 表是「1 美元 = N 本币」，到处都在做除法，有没有搞反的地方）
- `fx.js` 的增量逻辑与停更检测
- 空值/边界：起止同日、起点早于数据、某口径整列为 null

**不要浪费时间在这些已验证的事情上**（除非你怀疑验证本身有问题）：
- Node 实现与 Python 原版的等价性（600 个数值已逐项比对一致）
- 月末点位反推 YTD 与快照的一致性（99 个数值已比对）
- 自定义月度区间与预置「今年以来」的一致性（已比对）
- 收盘价与 Yahoo Finance 的交叉验证（韩国/台湾/印尼/标普 已精确匹配）

## B 部分：专业金融视角的 UI 审查

**请以一个真正看盘的人（基金经理、卖方研究员、严肃个人投资者）的眼光来看。**

现状：首屏是结论条（领涨/垫底/涨跌家数/中位数/近7日名次变化）+ 吸顶筛选条
+ 榜单（国名主导、涨幅、色条）。详情页有走势图、各区间涨幅、逐年涨幅。

请回答：

1. **这个榜单少了什么会让专业人士不信任它？** 具体点名。
2. **只给涨幅不给风险**，是不是根本性缺陷？如果要补，补什么最划算
   （波动率？最大回撤？还是别的）？在手机这个尺寸上怎么放得下？
3. **中位数**是不是合适的概括统计量？有没有更能说明问题的？
4. **红涨绿跌**：这是中国习惯，但看全球市场的人往往习惯绿涨红跌。
   要不要做成可切换？还是这属于过度设计？
5. **价格指数不含股息**这件事，现在只在长周期窗口提示一行小字。
   对专业用户来说，这个披露力度够吗？
6. **走势图**目前是纯折线，无坐标轴、无网格、无交互。
   在小程序这个场景下，加什么是值得的，加什么是负担？
7. 如果你只能提**三条**改进建议，是哪三条？按「对专业可信度的提升 ÷ 实现成本」排序。

## 硬约束（提建议时请在这些边界内）

- 云开发免费版云函数**超时固定 3 秒且不可调**（调高需付费版）。
  所有数据读取都是零依赖 + 从 CDN 取构建产物，因为带 wx-server-sdk 的函数
  冷启动就会超时。任何需要更多计算/更大数据量的建议，必须说明怎么塞进 3 秒。
- 数据每日收盘后更新一次，无盘中实时。
- 不做个股、不荐股、不给买卖建议（规避微信金融类目审核风险）。
- 扩展层 14 个市场（新马泰、北欧、东欧等）当前拿不到，已决定维持 27 国，
  不要把「补齐数据」当作建议。
- 东方财富按 TLS 指纹拦截非浏览器客户端，不可用且不打算绕过，别再提它。
